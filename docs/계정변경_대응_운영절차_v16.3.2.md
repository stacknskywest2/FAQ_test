# COP_FAQ 계정 변경 대응 운영절차 v16.3.2

## 1. 적용 상황

다음 상황에서 이 절차를 적용한다.

- Google Apps Script 작성자 또는 배포 계정 변경
- Google Sheets 소유자 또는 운영계정 변경
- 담당자 이동, 퇴직, 권한 회수
- 팀 운영계정으로 재정비
- Apps Script Web App URL 재발급

## 2. 운영 원칙

1. 가능하면 `stacknsky_west2@keco.or.kr`를 운영계정으로 고정한다.
2. 개인 계정으로 배포한 Apps Script는 담당자 변경 시 재배포 대상이다.
3. 설치형 트리거는 만든 계정에 귀속되므로 새 운영계정에서 다시 설치한다.
4. Web App URL은 `index.html`에 직접 박지 않고 `feedback-config.json`에서 관리한다.
5. 계정 변경 시 전체 패키지 재생성보다 `feedback-config.json` 교체를 우선한다.

## 3. 계정 변경 표준 절차

1. 새 운영계정으로 Google Sheets 접근 권한 확보
2. 새 운영계정으로 Apps Script 프로젝트 접근 또는 새 프로젝트 생성
3. `Code.gs`와 `Run.gs` 코드 확인
4. 새 운영계정으로 `setupNow` 실행
5. 새 운영계정으로 `testMailNow` 실행
6. 새 운영계정으로 `installTriggersNow` 실행
7. 새 운영계정으로 웹 앱 재배포
8. 새 Web App URL 복사
9. `feedback-config.json`의 `primary_endpoint` 교체
10. GitHub Pages 배포 경로에 `feedback-config.json`만 업로드
11. FAQ 서비스 접속 후 자동 로그 저장 확인
12. Google Sheets `사용량원본`, `응답원본`, `메일발송이력` 확인

## 4. feedback-config.json 예시

```json
{
  "active": true,
  "primary_endpoint": "https://script.google.com/macros/s/새배포ID/exec",
  "secondary_endpoint": "",
  "fallback_form_url": "https://forms.gle/HVRscayxikxSePBr8",
  "service_version": "v16.3.2",
  "updated_at": "2026-07-08",
  "memo": "운영계정 변경 시 primary_endpoint만 교체"
}
```

## 5. 점검 체크리스트

- [ ] 새 운영계정이 Google Sheets 편집 권한을 보유한다.
- [ ] 새 운영계정이 Apps Script를 실행할 수 있다.
- [ ] `setupNow` 실행이 성공했다.
- [ ] `testMailNow` 실행 후 테스트 메일이 발송되었다.
- [ ] `installTriggersNow` 실행 후 주간·월간 트리거가 설치되었다.
- [ ] 새 Web App URL이 발급되었다.
- [ ] `feedback-config.json`의 `primary_endpoint`가 새 URL로 변경되었다.
- [ ] GitHub Pages에 `feedback-config.json`이 반영되었다.
- [ ] 서비스 접속 후 `사용량원본`에 기록이 쌓인다.
- [ ] 검색 실패, FAQ 열람, e-book 열람 이벤트가 저장된다.

## 6. 장애 시 판단

- `사용량원본`에 기록이 없으면 `feedback-config.json` URL, Web App 배포 권한, Apps Script 실행 이력을 확인한다.
- 주간·월간 메일이 오지 않으면 새 운영계정에서 트리거를 재설치한다.
- 수식 오류는 수신창구 장애와 분리하여 판단한다. 원본 시트에 행이 쌓이면 수집은 정상이다.
