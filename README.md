## 0. 먼저 읽어야 할 결론

이 README는 단순 소개문이 아닙니다.  
이 문서는 **다음 담당자가 이 프로젝트를 인수받았을 때 가장 먼저 읽어야 하는 운영 안내서**입니다.

이 서비스를 수정하거나 배포하기 전에는 반드시 아래 순서를 확인하십시오.

```text
1. 현재 배포 버전 확인
2. 수정 대상이 콘텐츠인지, 화면인지, 이미지인지, 배포파일인지 구분
3. FAQ 문구는 엑셀 마스터 또는 기준 데이터에서 먼저 수정
4. index.html, JSON, 이미지, manifest, service-worker의 경로와 버전 일치 확인
5. 검색, 카테고리, 관련질문, e-book, 모바일 화면 테스트
6. 공개용 데이터에 내부 검토 메타데이터가 남아 있지 않은지 확인
7. service-worker 캐시 버전 갱신 여부 확인
8. ZIP 패키지 생성 후 실제 압축 해제 검증
9. 변경이력과 검증 결과 기록
10. 최종 배포 승인 후 GitHub Pages에 반영
```

이 프로젝트에서 가장 중요한 판단 기준은 하나입니다.

> **사용자가 원하는 질문에 빠르고 정확하게 도달할 수 있는가**

화면을 예쁘게 만드는 것보다, 피드백 버튼을 늘리는 것보다, 기능을 많이 붙이는 것보다  
**사용자가 실제 업무 질문을 찾을 수 있는 구조를 유지하는 것**이 우선입니다.

## 1. 이 서비스는 무엇인가?

**수도권관제센터 홈페이지 연계형 FAQ 서비스**는 굴뚝 원격감시체계, 사업장 대기오염물질 총량관리제도, 사업장대기오염물질관리시스템, 대기오염공정시험기준, 환경오염시설 통합관리 등 대기관리 업무에서 반복적으로 발생하는 질문을 한곳에 모아 안내하는 챗봇형 FAQ 서비스입니다.

서비스의 기본 문구는 다음과 같습니다.

> **뚜미와 함께 찾는 굴뚝·총량 업무 FAQ**  
> 수도권관제센터 업무지원 서비스

이 서비스는 일반적인 AI 챗봇처럼 외부 API를 호출하여 답변을 생성하지 않습니다.  
미리 검수한 FAQ 데이터를 기반으로 사용자가 검색, 카테고리, 질문트리를 통해 정해진 답변에 도달하도록 돕는 구조입니다.

따라서 이 서비스의 성격은 다음과 같습니다.

| 구분 | 설명 |
|---|---|
| 서비스 유형 | 정적 웹 기반 FAQ 서비스 |
| 배포 방식 | GitHub Pages 등 정적 웹 호스팅 |
| 답변 방식 | 사전 검수된 FAQ 데이터 표시 |
| AI API 사용 | 사용하지 않음 |
| 서버 | 없음 |
| 로그인 | 없음 |
| DB 서버 | 없음 |
| 주요 데이터 | HTML 내장 데이터 또는 JSON 기반 FAQ 데이터 |
| 운영 목적 | 반복 문의 감소, 업무 안내 표준화, 신규 담당자 지원, 모바일 접근성 향상 |

## 2. 왜 만들었는가?

수도권관제센터 관련 업무는 법령, 업무편람, 고시, 시스템 매뉴얼, 시험기준, 질의회신, 내부 운영 기준이 서로 연결되어 있습니다.  
하지만 실제 사용자는 대부분 다음과 같은 방식으로 질문합니다.

```text
개선계획서는 언제 내나요?
배출허용총량은 어떻게 확인하나요?
상태표시 이상이 뜨면 어떻게 해야 하나요?
사업장대기오염물질관리시스템에서 메뉴가 어디 있나요?
TMS 부착대상인지 어떻게 확인하나요?
관련 법령은 어디를 봐야 하나요?
```

문제는 사용자가 이런 질문을 했을 때, 답이 여러 문서에 흩어져 있다는 점입니다.

이 서비스는 그 흩어진 자료를 사용자의 질문 흐름에 맞게 다시 정리하여,  
업무 담당자와 사업장 담당자가 빠르게 1차 안내를 받을 수 있도록 만든 것입니다.

### 이 서비스가 해결하려는 문제

| 문제 | 서비스에서의 해결 방식 |
|---|---|
| 반복 문의 증가 | 자주 묻는 질문을 FAQ로 표준화 |
| 문서가 흩어져 있음 | 법령·업무편람·매뉴얼을 질문 중심으로 연결 |
| 신규 담당자 인수인계 어려움 | 질문트리와 답변 구조로 업무 흐름 안내 |
| 시스템 메뉴 찾기 어려움 | 메뉴찾기형 FAQ 제공 |
| 모바일 현장 확인 불편 | 반응형 화면과 PWA 구조 적용 |
| 답변 일관성 부족 | 검수된 문구를 기준으로 안내 |
| 배포·수정 시 오류 발생 | 버전관리, 보안점검, 패키지 검증 절차 적용 |

## 4. 서비스의 핵심 원칙

이 프로젝트는 기능보다 운영 원칙이 중요합니다.  
다음 원칙이 깨지면 서비스의 신뢰성이 낮아질 수 있습니다.

### 4.1 근거 문서 제한 원칙

FAQ 질문과 답변은 프로젝트에 업로드된 근거자료를 기준으로 작성합니다.  
문서에 없는 수치, 기한, 기관명, 행정해석, 법령 해석은 임의로 추가하지 않습니다.

### 4.2 1차 안내 원칙

FAQ는 최종 유권해석이 아닙니다.  
법령 개정, 사업장별 허가조건, 관할기관 판단, 개별 사실관계에 따라 실제 처리 결과가 달라질 수 있습니다.

따라서 답변에는 필요한 경우 다음 표현을 사용합니다.

```text
최종 확인이 필요합니다.
개별 사실관계 확인이 필요합니다.
최신 법령 또는 관할기관 안내를 함께 확인해야 합니다.
문서 기준으로는 다음과 같이 안내되나 실제 적용은 달라질 수 있습니다.
```

### 4.3 엑셀 마스터 우선 원칙

FAQ 문구는 가능한 한 엑셀 마스터에서 먼저 관리합니다.  
HTML과 JSON은 최종 서비스에 반영되는 산출물로 봅니다.

즉, 문구만 고치려고 HTML을 직접 건드리기 시작하면 이후 버전관리가 꼬일 수 있습니다.

### 4.4 공개용 데이터 최소화 원칙

공개 배포용 HTML 또는 JSON에는 사용자 화면에 필요한 데이터만 남깁니다.

공개용 데이터에 남기면 안 되는 예시는 다음과 같습니다.

```text
generated_from
build_summary
review_required
review_reason
visibility_status
old_id
duplicate_key
source_docs
source_pages
source_summary
db_group
source_class
내부 검토 메모
삭제후보 사유
비공개 판단 사유
```

### 4.5 사람 승인 원칙

ChatGPT 또는 자동화 도구가 초안, 수정안, 검토안을 만들 수는 있지만,  
공개·배포·중요 변경은 담당자의 승인 후 확정해야 합니다.

특히 다음 항목은 반드시 별도 검토가 필요합니다.

```text
법정기한
행정처분
과태료
권한 위임
허가·신고 구분
개별 사업장 적용 여부
대외 공개 적정성
```

## 5. 주요 기능

### 5.1 카테고리 기반 질문 탐색

대표 업무 카테고리를 선택해 질문을 찾아갈 수 있습니다.

주요 카테고리 예시는 다음과 같습니다.

```text
사업장 대기오염물질 총량관리
굴뚝 원격감시체계
사업장대기오염물질관리시스템 메뉴찾기
대기오염공정시험기준
환경오염시설의 통합관리
양식·업무편람 다운로드
이용안내
```

### 5.2 키워드 검색

사용자가 직접 키워드를 입력해 FAQ를 찾을 수 있습니다.

예시 검색어는 다음과 같습니다.

```text
개선계획서
배출허용총량
TMS 부착대상
상태표시
자가측정
배출량 산정
최적방지시설
업무편람
대기오염공정시험기준
```

### 5.3 관련 질문 연결

하나의 답변에서 끝나지 않고, 사용자가 이어서 궁금해할 만한 질문으로 이동할 수 있도록 관련 질문을 연결합니다.

예를 들어 “측정기기 부착대상”을 확인한 사용자는 “부착유예”, “부착면제”, “행정자료 활용”, “개선계획서” 같은 질문으로 이어질 수 있습니다.

### 5.4 관련법령 표시

FAQ별로 관련 법령명, 조항, 조항 내용을 연결할 수 있습니다.  
단, 법령 본문은 HTML로 실행되지 않도록 텍스트로만 표시해야 합니다.

### 5.5 업무편람 e-book 바로보기

서비스 내부에서 업무편람 원본을 바로 열람할 수 있도록 구성합니다.

대표 자료는 다음과 같습니다.

```text
굴뚝 원격감시체계 업무편람
사업장 대기오염물질 총량관리제도 업무편람
```

### 5.6 모바일 최적화

현장 또는 이동 중에도 사용할 수 있도록 모바일 화면을 고려합니다.

확인해야 할 사항은 다음과 같습니다.

```text
검색창이 잘 보이는가
카테고리 버튼이 너무 길게 늘어지지 않는가
터치 영역이 충분한가
업무편람 e-book 화면에서 페이지 이동이 가능한가
답변 카드가 화면 밖으로 깨지지 않는가
인트로 화면이 과도하게 길지 않은가
```

### 5.7 PWA 구조

`manifest.webmanifest`와 `service-worker.js`를 통해 앱처럼 설치하거나 캐시를 사용할 수 있는 구조를 지원합니다.

주의할 점은 service-worker 캐시 때문에 이미지나 HTML을 바꿨는데도 사용자의 화면에 예전 버전이 계속 보일 수 있다는 것입니다.  
이미지 교체, 인트로 수정, 업무편람 표지 교체 후에는 반드시 캐시 버전을 확인해야 합니다.

## 6. 기술 구조

이 서비스는 서버 없이 동작하는 정적 웹앱입니다.

| 구성요소 | 역할 |
|---|---|
| `index.html` | 서비스 화면, 검색, FAQ 표시, 주요 UI |
| CSS | 화면 디자인, 반응형 레이아웃 |
| JavaScript | 검색, 카테고리 이동, FAQ 렌더링, e-book 동작 |
| FAQ JSON 또는 내장 데이터 | 질문·답변 데이터 |
| `assets/` | 이미지, 아이콘, 업무편람, 캐릭터 등 정적 자원 |
| `manifest.webmanifest` | PWA 앱 이름, 아이콘, 시작 URL 설정 |
| `service-worker.js` | 캐시 관리, 오프라인 또는 앱형 동작 지원 |
| `version.json` | 현재 배포 버전 확인 |
| GitHub Pages | 정적 웹 배포 환경 |

## 7. 권장 폴더 구조

실제 버전에 따라 다를 수 있으나, 기본적으로 다음 구조를 권장합니다.

```text
/
├─ index.html
├─ README.md
├─ CHANGELOG.md
├─ version.json
├─ manifest.webmanifest
├─ service-worker.js
├─ assets/
│  ├─ icons/
│  ├─ images/
│  ├─ characters/
│  ├─ manuals/
│  └─ covers/
├─ data/
│  └─ faq_data.json
├─ docs/
│  ├─ 운영지침서.md
│  ├─ 배포전_보안점검표.md
│  ├─ 버전관리지침.md
│  └─ 검증보고서/
└─ archive/
   └─ old_versions/
```

단일 HTML에 모든 데이터가 내장된 버전이라면 `data/faq_data.json`이 없을 수 있습니다.  
그 경우 `index.html` 안에 FAQ 데이터가 직접 포함되어 있는지 확인해야 합니다.

## 8. 주요 파일 설명

### 8.1 `index.html`

서비스의 핵심 파일입니다.

이 파일 안에는 보통 다음 내용이 포함됩니다.

```text
화면 구조
인트로 화면
메인 카테고리
검색창
FAQ 답변 영역
관련 질문 영역
업무편람 e-book 영역
FAQ 데이터 또는 데이터 로딩 로직
검색·렌더링 JavaScript
반응형 CSS
```

가장 많이 수정하게 되는 파일이지만, 가장 위험한 파일이기도 합니다.  
수정 전에는 반드시 원본을 백업하고, 수정 후 검색·카테고리·모바일 화면을 확인해야 합니다.

### 8.2 `service-worker.js`

브라우저 캐시를 관리합니다.

이 파일에서 자주 문제가 생깁니다.

대표 증상은 다음과 같습니다.

```text
파일을 바꿨는데 사용자 화면에는 예전 화면이 보임
이미지를 교체했는데 이전 이미지가 계속 보임
업데이트 알림이 반복해서 뜸
업무편람 표지가 예전 것으로 보임
```

원인은 대부분 캐시 버전 또는 캐시 삭제 로직입니다.

배포 시 확인할 것:

```text
CACHE_VERSION이 최신인지
캐시 대상 파일 목록이 실제 파일명과 일치하는지
이전 캐시 삭제 로직이 있는지
업데이트 알림이 반복되지 않는지
```

### 8.3 `manifest.webmanifest`

PWA 앱 설정 파일입니다.

확인할 것:

```text
앱 이름
짧은 이름
시작 URL
아이콘 경로
배경색
테마색
display 설정
```

아이콘 파일명을 바꾸면 manifest의 경로도 함께 바꿔야 합니다.

### 8.4 `version.json`

현재 배포 버전을 확인하기 위한 파일입니다.

예시:

```json
{
  "version": "v16.0.1",
  "buildDate": "2026-06-25",
  "description": "FAQ-D-010 답변 및 이미지 수정 반영"
}
```

### 8.5 `README.md`

현재 보고 있는 이 문서입니다.  
다음 담당자가 프로젝트를 이해하고 유지관리할 수 있도록 하는 인수인계 문서입니다.

### 8.6 `CHANGELOG.md`

버전별 변경이력을 기록합니다.

예시:

```text
## v16.0.1
- FAQ-D-010 답변 문구 수정
- FAQ-D-010 이미지 답변 교체
- version.json 갱신
- service-worker 캐시 버전 확인
- 배포 패키지 무결성 검증
```

## 9. FAQ 데이터 수정 방법

FAQ 문구 수정은 가능하면 다음 흐름을 따릅니다.

```text
1. 수정할 FAQ_ID 확인
2. 엑셀 마스터 또는 기준 데이터에서 해당 문항 검색
3. 질문, 답변, 관련법령, 이미지, 관련질문 수정
4. display_yn 여부 확인
5. 공개용 데이터 생성
6. HTML 또는 JSON에 반영
7. 검색 결과에서 해당 문항 확인
8. 카테고리 경로에서 해당 문항 확인
9. 모바일 화면 확인
10. 변경이력 작성
```

### 9.1 FAQ_ID를 반드시 확인할 것

문항 수정 시 제목만 보고 수정하면 중복 질문을 잘못 수정할 수 있습니다.  
반드시 `FAQ_ID` 기준으로 수정합니다.

예시:

```text
FAQ-D-010
FAQ-TMS-001
FAQ-TOTAL-023
```

### 9.2 답변 수정 시 확인할 것

답변을 수정할 때는 다음을 확인합니다.

```text
문서 근거가 있는가
법정기한 또는 행정처분 문구가 있는가
최신 법령 확인이 필요한가
관련법령이 답변 내용과 실제로 연결되는가
이미지 답변이 있다면 경로가 맞는가
모바일에서 이미지가 깨지지 않는가
```

### 9.3 이미지 답변 수정 시 확인할 것

이미지를 교체했는데 화면에 예전 이미지가 계속 보이면 캐시 문제일 가능성이 큽니다.

확인할 것:

```text
실제 이미지 파일이 교체되었는가
파일명이 동일한 경우 브라우저 캐시가 남아 있지 않은가
service-worker 캐시 버전이 갱신되었는가
HTML에서 참조하는 이미지 경로가 맞는가
대소문자가 일치하는가
ZIP 패키지 안에 새 이미지가 포함되었는가
```

## 15. 자주 발생한 오류와 해결법

### 15.1 이미지를 바꿨는데 예전 이미지가 계속 보임

가능한 원인:

```text
브라우저 캐시
service-worker 캐시
동일 파일명 재사용
HTML 이미지 경로 오류
ZIP 패키지에 새 이미지 누락
```

해결:

```text
service-worker CACHE_VERSION 갱신
브라우저 캐시 삭제 후 확인
파일명을 변경하고 HTML 경로도 함께 수정
ZIP 내부 이미지 파일 직접 확인
```

### 15.2 업데이트 알림이 계속 뜸

가능한 원인:

```text
service-worker 등록 로직 중복
버전 비교 로직 오류
캐시가 매번 새 버전으로 인식
version.json 응답 문제
```

해결:

```text
service-worker 등록 코드 확인
업데이트 알림 표시 조건 확인
version.json 값 확인
동일 세션에서 반복 표시되지 않도록 조건 추가
```

### 15.3 카테고리 버튼이 사라짐

가능한 원인:

```text
FAQ 데이터 구조 변경
카테고리명 불일치
렌더링 함수 수정 중 오류
display_yn 필터 과도 적용
HTML 요소 id 변경
```

해결:

```text
브라우저 콘솔 오류 확인
FAQ_DATA 카테고리 값 확인
카테고리 렌더링 함수 복원
기준 버전과 비교
```

### 15.4 검색 결과가 나오지 않음

가능한 원인:

```text
검색 대상 필드명 변경
FAQ 데이터 로딩 실패
검색어 정규화 오류
display_yn 필터 문제
JavaScript 오류
```

해결:

```text
검색 함수 확인
FAQ_DATA 배열 존재 확인
검색 대상 필드 확인
콘솔 오류 확인
기준 버전 검색 로직과 비교
```

### 15.5 업무편람 e-book이 열리지 않음

가능한 원인:

```text
PDF 또는 이미지 파일 경로 오류
업무편람 파일 누락
모바일 이벤트 충돌
```

```text
assets/manuals 경로 확인
파일명 대소문자 확인

service-worker 캐시 목록 확인
```

### 15.6 ZIP을 받았는데 파일이 비어 있음

가능한 원인:

```text
압축 대상 폴더를 잘못 지정
```

```text
압축 전 파일 목록 확인
```

```text
검색 렌더링 함수
카테고리 트리 생성 함수
관련질문 연결 로직

display_yn 필터
내부 메타데이터 제거 로직

```

특히 `innerHTML`을 사용해 FAQ 답변이나 법령 본문을 직접 출력하는 방식은 주의해야 합니다.  
가능하면 `textContent` 또는 안전한 렌더링 방식을 유지합니다.

## 20. README 유지관리 방법

README도 산출물이므로 최신 상태를 유지해야 합니다.

README를 수정해야 하는 경우는 다음과 같습니다.

```text
서비스 구조가 바뀐 경우
배포 방식이 바뀐 경우
파일 구조가 바뀐 경우
버전관리 규칙이 바뀐 경우
자주 발생한 오류가 새로 발견된 경우
보안점검 기준이 바뀐 경우
다음 담당자에게 꼭 알려야 할 운영상 주의사항이 생긴 경우
```

README는 너무 짧으면 인수인계에 실패하고, 너무 흩어져 있으면 읽히지 않습니다.  
따라서 이 문서는 **길지만 찾기 쉬운 구조**를 유지하는 것이 좋습니다.

## 22. 최종 운영 원칙 요약

이 프로젝트는 단순히 HTML 하나를 배포하는 일이 아닙니다.  
업무편람, 법령, 시스템 매뉴얼, 사용자 질문을 연결해  
사용자가 필요한 답변에 도달하도록 만드는 **업무 지식 길찾기 서비스**입니다.

따라서 운영자는 다음 원칙을 기억해야 합니다.

```text
1. 질문 도달성이 최우선이다.
2. FAQ는 근거문서 기반 1차 안내 자료다.
3. 문구 수정은 엑셀 마스터 또는 기준 데이터에서 시작한다.
4. 공개용 데이터에는 내부 관리정보를 남기지 않는다.
5. service-worker 캐시를 항상 의심한다.
6. 배포 전에는 실제 ZIP 압축 해제 검증까지 한다.
7. 변경이력 없이 배포하지 않는다.
8. 법정기한·행정처분·권한 문구는 반드시 별도 검토한다.
9. 다음 담당자가 이해할 수 있게 기록한다.
10. 사용자가 원하는 질문에 도달하지 못하면 기능이 많아도 실패다.
```
